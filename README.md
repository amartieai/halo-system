# THE HALO SYSTEM

A self-governance model that any city, province, state, or nation can
take down, run its own way, and publish what it learns.

HALO is two things joined together:

1. **A fund held in trust for the people** — administered openly,
   with income calibrated to support life without removing people
   from their work, and infrastructure and unmet needs funded first.
2. **A network of civic simulations** — one mirror per community,
   fed with that community's own documented history and live
   statistics, so allocation decisions are *tested in the mirror
   before money moves*, and counterfactuals can be run on the
   community's own record: **what if this had gone the other way?**

Nobody has to believe this system works. That is the point of
publishing it as a runnable model: **load your own place's numbers
and see.** Is it really true? Can it be done? Can it be simulated?
Run it.

## Start here

HALO today is an **open public design** — a framework you can
read, copy, and stand up as your own community node. It is not
yet a software application: "running it" currently means
working the method in these documents — fill in a node for your
place, grade a question through the gate, run the simulation
steps, publish what you find (see
[SIMULATION-GUIDE.md](SIMULATION-GUIDE.md)). Working simulation
tooling is on the roadmap; the method does not wait for it.

The minimal path, first time through:

1. Read [DESIGN.md](DESIGN.md) — the whole system on one pass.
2. Copy [city-template/CITY-NODE.md](city-template/CITY-NODE.md)
   and fill it with your place's public numbers — or read the
   filled sample first:
   [examples/SAMPLE-NODE.md](examples/SAMPLE-NODE.md) (synthetic
   data, labelled as such).
3. Put one real question through
   [NINE-JUDGES.md](NINE-JUDGES.md).
4. Run it by [SIMULATION-GUIDE.md](SIMULATION-GUIDE.md), and
   publish your result with the "Simulation result" issue
   template.

## Status and roadmap

- **Status:** v1.1 — design/framework release. The documents
  are the product at this stage; treat every claim in them as
  the design's claim, labelled in place as measured, sourced,
  or hypothesis.
- **Now:** community nodes standing up on the template;
  results shared between nodes.
- **Next:** a worked pilot with one community's real public
  data, published end to end — question, assumptions, outputs,
  limitations.
- **Later:** open simulation tooling implementing the
  calibration layers, so a node can run the method in software
  instead of by hand.
- **What success looks like:** one community runs the full
  path on its own record and publishes results other
  communities can check, adopt, adapt, or reject.

## How it is organized

- **Local first.** Every community calibrates itself — its own
  categories, its own needs, its own beliefs. There is no national
  template.
- **Questions pass a gate.** Before any question enters a
  simulation, it passes a methodology review (see
  [NINE-JUDGES.md](NINE-JUDGES.md)). Grade before you simulate.
- **One shared floor.** Beneath all local variation sits a single
  governing rule of law that every participating community abides
  by (see [GOVERNING-RULE.md](GOVERNING-RULE.md)). Everything else
  is local.
- **Results are shared.** City to city, province to province,
  country to country. A place that finds something publishes it;
  the next place adopts it, adapts it, or rejects it — by its own
  people's choice. Adoption by example, never by imposition.
- **The channel is ungated.** This project exists because the
  worldwide web was designed for everybody to use freely. It is
  published freely for the same reason. If one copy is removed,
  every fork remains.

## The root problem this answers

Every pathology this system is built to unwind — desperation crime,
captured funds, courts that do not answer, professions bloated by
the process they feed on — traces to one root: **money, and the
control of it, keeping people in fear and lies.** A fair system is
a smaller system. This repository is the working model of the
smaller one.

## Limits, stated plainly

A simulation shows what follows from its inputs and rules —
it cannot prove what *will* happen in a real place. HALO's
design claims are labelled where they stand: some rest on
cited record, some are hypotheses the nodes exist to test.
Any result published without its assumptions and limitations
attached is not a HALO result, whatever it calls itself.
